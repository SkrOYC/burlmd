# Stage 3: Technical Implementation Changelog

## v1.1.0
Evolution pass consuming PRD v1.1.0 and this session's pre-Tasks interview. Minor bump: five ADRs, a new storage-format contract, and a materially expanded FFI surface, with no reversal of a prior stack selection.

The pass was triggered by a finding that Stage 4 could not proceed: too much of what the next epics need did not exist at this layer, and `planning-engineering-execution` forbids inventing contracts. The largest gaps were that the project's own on-disk format was never specified, and that the FFI contract had no function for creating, deleting, renaming, or listing a Note.

**ADR-004 — OKF v0.2 conformance.** Investigation established that "Open Knowledge Format", named in `prd/vision.md` since v1.0.0 but never defined anywhere downstream, is a real published specification (Google Cloud, announced 2026-06-12, `GoogleCloudPlatform/knowledge-catalog`, `okf/SPEC.md`), currently at v0.2. Pinned to v0.2. Its §2 settles Note identity as the bundle-relative path with `.md` removed, which authoritatively resolves a question this project had answered inconsistently in three places. Its §11 conformance rules are only three and all cheap. The costs accepted — a frontmatter block on every Note that the primary actor now sees constantly, and verbose bundle-absolute link targets in raw view — are recorded in the ADR and in `prd/out-of-scope/wikilink-syntax-on-disk.md`.

**ADR-005 — local-first Workspace, opt-in Remote.** The application is currently unusable: `lib/main.dart` gates everything behind a login screen, and Epic C deferred item 1 means no OAuth App is registered, so the gate cannot be passed at all. The cause is a specification error rather than a coding error — OAuth was the only documented path to a Workspace. Workspaces are now initialized locally with `provider = 'local'` (a value `schema.sql` has carried since v1.0.0 and no code has ever used), with `init` rather than `clone`, and with the root encryption key generated during bootstrap rather than inside the OAuth handshake.

**ADR-006 — raw-on-focus editing.** Records how CAP-EDIT-01 (focused Block shows raw source) and CAP-EDIT-04 (selection spanning Blocks) are satisfied simultaneously without the Presentation Container becoming an owner of note content. Rendered Blocks sit inside one `SelectionArea`; focus promotes exactly one Block to a plain editable field; multi-Block range operations dispatch to Rust. Verified against Flutter's `SelectableRegion` documentation, which specifies the `Selectable` mixin and `SelectionRegistrar` registration and confirms `Text` participates automatically — the docs are silent on whether `EditableText` participates, and the design deliberately does not depend on it. `appflowy_editor` 6.2.0 and `super_editor` 0.2.7 were both evaluated and rejected, on architectural grounds and on maintenance/Linux-support grounds respectively; the reasoning is recorded so it is not silently revisited.

**ADR-007 — span-preserving source splicing.** The single largest change. `flow-edit-note.md` had specified serializing the AST back to Markdown; PRD v1.1.0's Edit Fidelity constraint makes that unusable, since a serializer rewrites the whole file by definition and nothing ever specified a canonical form for it to write. Editing being raw means the editor already holds the bytes belonging in the edited Block's span, so saving becomes a splice. Verified in the vendored source that `pulldown-cmark` 0.12.2 provides both required APIs — `Parser::into_offset_iter()` at `src/parse.rs:1310` and `Options::ENABLE_YAML_STYLE_METADATA_BLOCKS` at `src/lib.rs:559` — rather than assuming them. Consequences: no serializer exists on the save path by design; `update_block` changes from taking an `AstNode` to taking source text; spans live Core-side keyed by `block_path` and never cross the FFI boundary; and `base_revision` becomes a content hash, which fixes an open→save path that was broken by construction (`open_note` returned the literal `"head"` while `save_note` compared a stringified `notes.last_modified`).

**ADR-008 — four-tier persistence.** Keystroke to the `drafts` table, ~1s idle to an atomic file write, Note close to one Git commit, commit to `notify_activity()`. Commit-on-close rather than on a timer, so history reads as one entry per Note per sitting. This gives the `drafts` table its first reader and writer and `SyncScheduler::notify_activity()` its first caller — both have existed with neither since their respective epics. The accepted cost is that a Note left open for hours is written but uncommitted, and therefore unpushed.

**New: `data-models/okf-bundle.md` and `data-models/okf-frontmatter.schema.json`.** `architecture/containers.md` gives the Local Repository two storage forms; only the SQLite index had a schema. The bundle contract covers layout, identity, frontmatter, links, reserved filenames, attachments and invariants, with the JSON Schema (2020-12) providing a machine-checkable frontmatter model that encodes OKF's required/recommended/optional distinction and explicitly permits unknown properties.

**`data-models/schema.sql` corrected.** `notes.id` is documented as the OKF concept id, deleting the "stable UUID (persisted in Markdown YAML frontmatter)" claim that was never implemented, contradicted the specification, and contradicted `open_note`'s actual behavior. Added `notes.content_hash` (the OCC token) and `notes.okf_conformant` (so a foreign or hand-authored file is indexed rather than rejected, per CAP-WS-05/CAP-PORT-03). Re-keyed `links` on `(source_id, target_id)` — subsequently corrected to `(workspace_id, source_id, target_id)` in the round-1 section below, which is the shape that ships — with `target_id` now `NOT NULL` — under path-based links a target id is always derivable even for a ghost Link, which the prior title-keyed model could not express — and added `idx_links_target`, without which backlinks (CAP-GRAPH-05) is a full edge scan on every Note open. `PRAGMA user_version` deliberately stays at `1`: nothing is deployed and no index file exists on any machine, so these are edits to the baseline rather than a migration away from it.

**`contracts/ffi_api.rs` expanded.** Added Workspace lifecycle (`open_or_create_local_workspace`, `open_workspace`, `reindex_workspace`, `workspace_tree`, `export_workspace`), Note and Directory CRUD (`create_note`, `delete_note`, `rename_note`, `move_note`, `create_directory`, `rename_directory`, `delete_directory`), source-based editing (`get_block_source`, the rewritten `update_block`, `split_block`, `merge_block_with_previous`), range operations (`copy_range_as_markdown`, `delete_range`, `replace_range`), persistence (`close_note`, `pending_drafts`), discovery (`find_notes_by_title`, `link_completions`, `backlinks`), and session/sync (`current_session`, `connect_remote`, `sign_out`, `sync_status`, `sync_now`, `notes_with_conflicts`). `open_note_by_id` was removed by merging it into `open_note`, which now takes a concept id — the pair only existed because identity was ambiguous, and under ADR-004 it is not. `search_notes` gained a Workspace filter, closing an Investigate item left open from PR #4's round-4 review, and an explicit `limit` replacing a hardcoded cap of 50 that truncated silently. (The filter began as a `workspace_id` parameter; round 2 below made it implicit in the active Workspace, which closes the same gap without letting a caller name a Workspace the Core is not on.) `AppError` gained `RevisionMismatch`, `PathUnavailable`, `NotFound` and `OAuthStateMismatch`. `InlineElement::Link` now carries `target_id` and `exists` instead of `target_title`/`resolved_note_id`, matching path-based identity and making ghost Links representable.

**A structurally dead field identified.** `AstNode::Suggestion::base_content` can only ever be populated if the merge that produced the conflict ran with `merge.conflictStyle = diff3`. The `git merge` default is `merge` style, which emits no base section — so as currently implemented in `rust/src/git/operations.rs`, that field could never be anything but `None`. Recorded in the contract at the field itself; the pull path must set `diff3` explicitly.

**`guidelines.md` updated.** Added `rust/src/okf/`, `rust/src/index/` and `rust/src/workspace/` to the layout tree. Added the span-locality rule (spans are Core-side, never on `AstNode`) and the no-rewriting-unedited-bytes rule to the Rust standards; the selection-state exemption and the typographic-identity requirement to the Dart standards; mandatory round-trip property tests for the splice path; and a standing requirement that every UI ticket's Verification Command launch the real application, which is the gap that let Epic B's regression ship past six passing widget tests. Specified the default Workspace location, and that the encrypted index lives outside the bundle rather than inside a Git repository whose premise is human-readable plaintext.

**`stack.md` updated (v1.1.0).** Added `saphyr` 0.0.11 as the YAML reader — read-only by design, since ADR-007 never re-serializes the block — with a note that `serde_yaml` and `serde_yml` are both deprecated and archived, and an explicit pre-1.0 risk entry. Documented the two load-bearing `pulldown-cmark` APIs against their verified source locations, and recorded that 0.13.4 is available while the pin stays at 0.12.2. Added a Storage Format section pinning OKF v0.2, and a compatibility policy for it.

**Deliberately not resolved.** The attachment directory for images is left unspecified: CAP-EDIT-06 is deferred scope, and the choice is constrained by needing to be unambiguously distinguishable from a Directory of Notes. No CI configuration is specified, per an explicit scoping decision to keep the next wave tight — recorded as a known risk rather than an oversight, since `guidelines.md` continues to state that nothing enforces the testing standard.

**Upstream amendments.** `architecture/` was edited during this pass, which the framework's non-trespass rule would ordinarily forbid. The edits are corrections of fact — two of them the direct cause of the application's current unusable state — and are logged in `architecture/changelog.md` v1.1.0 rather than buried here.

### Corrections from PR review, round 1
Folded into v1.1.0 rather than versioned separately, since nothing in this pass has merged.

- **`schema.sql` keys were wrong in two ways, both reproduced against SQLite before fixing.** A concept id is unique per bundle, not globally, so `notes.id` as a bare `PRIMARY KEY` made two Workspaces each containing `Welcome.md` a constraint violation — which directly contradicted `WSPC-D009`'s own acceptance criterion about searching one Workspace and not the other. Every table keyed by a concept id is now keyed by `(workspace_id, ...)`. Separately, positional identity means a rename *rewrites* `notes.id`, and with `PRAGMA foreign_keys = ON` the `links.source_id` foreign key had no `ON UPDATE CASCADE`, so renaming any Note that linked out failed outright — the core operation of `WSPC-D006`. Added `ON UPDATE CASCADE` on `links` and `fts_mapping`, and documented that `drafts` has no foreign key by design and must therefore be re-keyed explicitly in the same transaction.
- **The reparse was specified in two contradictory places.** `update_block` was documented as splicing *and reparsing* on every keystroke, while ADR-007, ADR-008, `risks.md` risk 7 and the spike brief all claimed the tiering kept reparse off the typing path. The contract's version would have put an O(file) parse, an encrypted draft write and a full-AST payload on a synchronous FFI call per keystroke. Resolved in favour of the claim: `update_block` now buffers and returns `()`, and a new `commit_block` splices and reparses on blur. This is sound because a focused Block displays raw source the UI already holds, so a per-keystroke AST conveys nothing.
- **ADR-007 decision 3's stated rationale was wrong** — it justified keeping spans off `AstNode` by payload cost, which does not survive scrutiny against a contract whose reparsing calls return the whole AST anyway. Replaced with the real reason (ownership and layering) and the rejected argument recorded so it is not revived.
- **Invented citation granularity.** `§11.1`, `§11.2` and `§11.3` do not exist; OKF §11 is a flat section. Corrected in five files. The substance was right and every other citation verified verbatim, but inventing subsection numbers in a document set whose value is precise citation is exactly the wrong error to leave standing.
- **`timestamp` was described as a current optional v0.2 field.** Per OKF §13.1 it is legacy, superseded by `generated.at`. Corrected, marked deprecated in the JSON Schema, and ADR-004 gained decision 8 ruling explicitly on `generated` — which is not written either, for Edit Fidelity reasons, with the resulting gap for the Agent actor stated plainly rather than left implicit.
- **`stack.md`'s OKF risk characterization understated observed behavior.** It quoted §12's policy that minor bumps are backward-compatible; the only minor bump the format has had carried two breaking changes in its own §13.1. Now says to treat every revision as potentially breaking.
- **`rename_directory` and `delete_directory` returned nothing**, leaving a caller with an open Note from that subtree holding a dead concept id. They now return an id remapping and the removed ids respectively, with matching acceptance criteria in `SHEL-E005`.
- **`begin_oauth_flow`'s doc comment misdescribed its own security model**, claiming the Core checks the verifier — it does not, it forwards it. Rewritten to state plainly that `state` validation is a UI obligation with no Core-side enforcement point, and that keeping the pair Core-side was considered and declined.
- **Ticket scope holes that would have forced unjustified deviations.** `rust/src/db/schema.sql` — the DDL the application actually executes via `include_str!`, still byte-identical to the pre-v1.1.0 schema — was in no ticket's scope, on the critical path. Added to `WSPC-D004`. Also added `rust/src/error.rs` to `WSPC-D002`, `rust/src/markdown/ast.rs` to `WSPC-D003`, and regenerated-bindings scope to `WSPC-D004` through `WSPC-D007`, each of which adds `#[frb]` functions.
- **`prd/constraints.md` overstated at-rest protection.** It asserted reliance on operating-system full-disk encryption as though it were a platform guarantee; on the primary desktop target it is an install-time opt-in the application cannot assure. Reworded to separate what is guaranteed (the encrypted index) from what is not.
- **`flow-auth-handshake.md`** used an undeclared `Local` participant, which Mermaid auto-created to the right of `Remote` — reading as though the local repository sat beyond the network boundary. Declared in position.

### Corrections from PR review, round 2
Folded into v1.1.0 on the same grounds as round 1.

- **The contract still carried `workspace_id` after `schema.sql` stopped needing it.** Round 1 re-keyed every table on `(workspace_id, ...)`, which is what makes a concept id unambiguous; the contract was not revisited, so thirteen signatures still took a `workspace_id` alongside a concept id. That is not merely redundant — it is a second, independently settable answer to "which Workspace", and any disagreement between the two is a silent cross-Workspace write. Removed from all thirteen. The Core owns exactly one active Workspace, stated as a contract-wide rule and as ADR-005 decision 7, and the multi-Workspace case remains where `prd/out-of-scope/multiple-simultaneous-workspaces.md` already put it.
- **The write tier had two owners.** `save_note(note_id, expected_base_revision)` took an Optimistic Concurrency Control token from the UI, while ADR-008 gives the Core the idle timer that decides when a write happens. The UI is never told the timer fired, so its token is stale by construction the moment the Core writes — the same class of defect as the `"head"` placeholder round 1 fixed, reintroduced one layer up. Renamed to `flush_note(note_id)`, with the hash comparison performed Core-side against the value recorded at open.
- **`update_block`'s doc contradicted `drafts.raw_markdown`.** It said the call "does not splice", but the draft row holds the Note's full source, so the new Block text must be substituted into it to be written at all. What must not happen is a *parse*. Reworded to say so, since the imprecise version reads as a licence to buffer Block text somewhere the crash-recovery tier cannot see.
- **The JSON Schema enforced advisory fields as though they were conformance-bearing.** `status`'s enum, `resource.format` and `generated`'s required keys are not conformance conditions in OKF v0.2; validating them would reject a bundle the specification accepts. Relaxed, and an `x-conformance-bearing` annotation now names the one property (`type`) that genuinely is.
- **`okf-bundle.md` said a reserved filename is "redirected to a different filename".** Silently writing a Note somewhere other than where the user named it is worse than refusing. It is now `PathUnavailable`, matching how every other name collision in the contract behaves. Invariant 5 was likewise rescoped to Notes burlmd wrote, since a foreign bundle is explicitly allowed to contain files it did not.
- **The spike Verification Commands passed against an unedited placeholder.** Both now fail on the template banner and assert no production code changed, which is the actual constraint on a Spike.
- **`prd/capabilities.md` still overstated at-rest protection.** Round 1 fixed the same claim in `constraints.md` and did not check whether it appeared elsewhere; `CAP-WS-04` asserted operating-system full-disk encryption as a product guarantee. Reworded to state the two protections separately, only one of which this application delivers.
- **`guidelines.md` named no index path**, while `rust/src/db/connection.rs` resolves `$HOME/.burlmd/index.sqlite3` — a placeholder from Epic B predating any Workspace path. Pinned to `$XDG_DATA_HOME/burlmd/index.sqlite3`, with `WSPC-D004` moving it and explicitly not migrating whatever a development build left behind.
- **The `drafts` foreign-key rationale described a state this design cannot reach.** It claimed a draft can precede its `notes` row; `create_note` writes the file and the row before the first keystroke, so it cannot. The real justification is the rename case. Corrected rather than left as a comment that would mislead the next reader into supporting an impossible state.
- **The `workspace_id` removal was incomplete on the return path**, found while re-validating the contract rather than by review. `NoteMetadata` still carried a `workspace_id` field, and `search_notes`' doc comment still explained a `workspace_id` parameter the signature no longer had. Both removed. A field the UI cannot act on is not neutral here: it is the same "which Workspace?" question the rule exists to make unaskable, surviving one layer down.
- **`flow-auth-handshake.md` generated a `state` parameter and never compared it.** As drawn, the value was minted, handed to the UI, and dropped. Round 1 rewrote `begin_oauth_flow`'s doc comment to say state validation is the UI's obligation, but the flow diagram — the thing an implementer follows — still had no comparison step anywhere. Added, before the token exchange rather than after.

### Corrections from PR review, round 3
Folded into v1.1.0. Both P1s were consequences of round 2's own fixes.

- **Round 2's `state` comparison contradicted the contract it described.** The flow diagram put the CSRF check in the Core lane while `begin_oauth_flow`'s doc comment recorded a Core-side check as an explicitly *rejected* alternative, and `authenticate_workspace` took no `state` argument to compare — so the sequence was unimplementable against its own signature. Two documents specifying one control in mutually exclusive places is the same failure that produced the original defect. Resolved by giving the Core the check outright: `OAuthFlowStart` now returns a single-use `flow_id` instead of the verifier and `state`, both of which stay Core-side, and `authenticate_workspace(flow_id, auth_code, returned_state)` compares before any token request, returning a new `OAuthStateMismatch`. The trade-off originally cited against this — Core statefulness across the browser leg — was illusory: the flow was already stateful across that leg, with the state parked in the one container that cannot enforce anything with it. It also removes an obligation that no ticket owned, since the OAuth UI is deferred to Epic G.
- **`BlockRange` needed a mapping three documents said was no longer needed.** Its offsets are into each Block's *rendered* text, because a range spans **unfocused** Blocks; splicing needs source offsets. ADR-006 and `EPIC-F-editor-depth.md` both claimed mapping formatted output to editable spans "is no longer a requirement at all" — true for the focused Block, false for exactly this case, and `EDIT-F007` sits at the end of the critical path relying on it. Added ADR-007 decision 8, and verified rather than assumed: `OffsetIter`'s `Iterator` impl emits `item.start..item.end` for every event including inline ones (`src/parse.rs:2048-2078`), and empirically, for `hello **bold** world`, rendered offset 6 resolves to source offset 8. The residual risk is much smaller than the one it replaces — this maps from parser output, not from laid-out geometry. `split_block` also now states that its `offset` is a *source* offset, since two neighbouring APIs using different coordinate spaces with one of them undocumented is a defect waiting on the first implementer who assumes consistency.
- **`NoteState.base_revision` still told the caller to pass it back to `save_note`**, a function round 2 deleted, while `flush_note` 180 lines later said requiring it from the caller "would be actively wrong". Same residual pattern round 2 caught in `NoteMetadata.workspace_id`.
- **`commit_block` read as though the file write happens on blur** ("alongside the tier 2 write"), contradicting ADR-008, `flow-edit-note.md` and `WSPC-D007`'s own criterion that the file is unchanged after a Block edit. Separately, ADR-008 left unanswered what the idle timer measures and whether it can fire mid-focus. It can, and must — otherwise a Note left focused never reaches disk. Specified at the time as: it splices the buffered source and shifts later spans arithmetically, without reparsing, because nothing renders from the focused Block's node while it is focused. **Round 7 below supersedes the splicing half** — tier 2 writes the working source verbatim and splices nothing, since a second writer of that buffer duplicates the typed bytes. Recorded rather than silently rewritten, following the convention this changelog adopted in round 3 for exactly this situation. ADR-008's own "reparse sits at tier 2" bullet was stale from round 1 and is corrected.
- **Conformance repair was specified two different ways.** `okf-bundle.md` said automatic on next edit; the contract said the UI offers it. Resolved to explicit-user-action, with the reason stated: prepending frontmatter to a file that has none writes bytes outside any edited Block's span, which `guidelines.md` states as an absolute and ADR-007 decision 5 does not cover. No ticket implements it, and that is now said out loud.
- **`CAP-PORT-01` promised bundle-wide conformance "at all times".** OKF §11 defines conformance over an entire bundle, so one foreign file without frontmatter falsifies it — and CAP-WS-05 plus CAP-PORT-03 make that supported and possibly permanent. Round 2 scoped the downstream statements in `okf-bundle.md` and `constraints.md` without sweeping the P0 capability they derive from, so the two disagreed. Same "fixed the sentence it was shown" pattern as `CAP-WS-04`.
- **The `drafts` orphan claim was false for deletion.** Reproduced against SQLite with foreign keys on: with no foreign key, deleting the `notes` row *or* the `workspaces` row leaves the draft behind. The rename justification was sound; deletion is a second path to the state the comment declared unreachable. `delete_note`/`delete_directory` now clear draft rows explicitly, with a matching criterion on `WSPC-D006`.
- **`v1.1.0`'s own body still described the `workspace_id` filter round 2 removed**, contradicting the round-2 section in the same file. Since nothing has merged, that section describes final state, so it is now written as final state with the history noted.

### Corrections from PR review, round 4
Folded into v1.1.0.

- **The `links` primary key made a legal rename fail, reproduced against the file as written.** `PRIMARY KEY (workspace_id, source_id, target_id)` is justified in round 1's comment by `INSERT OR IGNORE`, but the rename path is an `UPDATE`, which has no equivalent escape. Renaming `Old` to `New` collides whenever one Note already links to both `Old` and a ghost `New` — which is not contrived, it is exactly the CAP-GRAPH-04 workflow of writing forward into an uncreated concept and then creating it. A P0 rename therefore broke on a graph the product itself encourages, and `WSPC-D006`'s existing STOP about atomicity would have led an implementer to conclude the rename was *correctly* refused. Specified as `UPDATE OR REPLACE`, with a STOP saying a link collision is a merge and not a refusal.
- **`PRAGMA user_version = 1` sat inside a batch that is replayed on every open.** `connection.rs` runs `execute_batch(SCHEMA)` unconditionally, so the statement would silently reset a migrated database to the baseline on its next open — making the one value a future migration branches on a constant, which is the opposite of what the comment beside it promises. Now specified as read-first, written only when it reads 0.
- **`PRAGMA foreign_keys = ON` was load-bearing and unstated.** It is per-connection and not stored in the file, SQLite defaults it off, and with it off the cascades do not error — they silently do not fire, leaving orphaned rows with nothing to signal the loss. `open_encrypted_db_with_key` is reachable without `init_schema` today. Now a connection-open obligation in `guidelines.md` with a criterion on `WSPC-D004`.
- **`strategy.md` was the one stage file whose version marker never moved** — still `v1.0.0` against an `architecture/changelog.md` declaring v1.1.0, because that changelog recorded the file as needing no amendment. It did: it still described a full clone as the cost of *provisioning* a Workspace, which ADR-005 replaces with `init` for the first device.
- **`resilience.md`'s Epic B status note was the last stale one.** It said nothing read or wrote `drafts` and the mechanism needed its own ticket; `WSPC-D007` is that ticket. Every other such note was explicitly superseded during this pass, and this one was missed for the same reason `strategy.md` was.

### Corrections from PR review, round 5
Folded into v1.1.0.

- **The tier 2 Optimistic Concurrency Control baseline was never advanced, so the second write of a session failed against the first.** `flush_note` and `WSPC-D007` both said the Core compares the file against the hash it recorded *when the Note was opened*. But the tier 2 timer fires repeatedly within one session, and after the first write the on-disk hash is no longer the open-time hash — because the Core itself changed it. Under the literal specification every write after the first raises `RevisionMismatch` against this application's own output, and `WSPC-D007`'s external-change criterion would have been satisfied by correct behaviour. This is the same shape rounds 2 and 3 removed one layer up, twice: a token whose two ends drift apart by construction. The Core now re-records the baseline after every successful write, and the criterion distinguishes "changed by something other than this application" from "changed at all".
- **`okf_conformant` omitted the one condition OKF §11 actually makes conformance-bearing.** Three definitions — the contract, `schema.sql` and `okf-bundle.md` — all said the flag is false when frontmatter is absent or unparseable. §11's second requirement is a non-empty `type`, so a block containing only `title:` parses perfectly and is non-conformant. That contradicted this PR's own `okf-frontmatter.schema.json`, where `type` is `required` and the sole entry in `x-conformance-bearing`. All three corrected, and `WSPC-D002` gained the parseable-but-typeless criterion — the only case where the check is more than a parse attempt, and therefore the only one a naive implementation fails.
- **Deleting a Note stranded its full text in the encrypted index permanently.** `fts_mapping` exists to avoid an O(N) scan on delete, but it carries `ON DELETE CASCADE` from `notes` — so deleting the `notes` row destroys the only pointer to the FTS row in the same statement, leaving it unreachable *and* undeletable. Reproduced: after the delete the mapping is gone, the FTS row remains, and its content still matches a `MATCH` query. The consequence is not disk growth but privacy: the content of every deleted Note accumulates forever in the one file this product encrypts *because* it aggregates the content of every Note. The ordering obligation is now stated on the table, on `delete_note`, and as a `WSPC-D006` criterion.
- **The 16ms budget was claimed in two directions at once.** This pass rewrote `prd/constraints.md` to cover "the transition of a Block into and out of its raw editing state" — which is blur, which is `commit_block`, a synchronous O(file) splice-and-reparse. Both ADR-007 and ADR-008 asserted that reparse falls *outside* the budget. `WSPC-D001`'s STOP already sided with the constraint, so the ADR consequence bullets were the stale half; left standing they gave an implementer a citable reason to dismiss a slow blur as out of scope. Now stated honestly: off the *keystroke* path, squarely inside the budget for the focus transition, which is exactly why the spike measures it.
- **Two more surviving instances of the at-rest overclaim**, making four rounds in which this claim has been corrected somewhere and left standing elsewhere. `containers.md` still said the OKF tree "relies on OS-level Full Disk Encryption", pointing at a `constraints.md` that now says the opposite. ADR-003 decision 2 said the same thing more strongly ("rely exclusively on"). Both now state the absence rather than the reliance, and this time the whole tree was swept rather than only the file that was reported.
- **`WSPC-D004`'s scope note pointed at the defect round 4 had just fixed.** It tells the implementer to bring `rust/src/db/schema.sql` "in line with" the contract schema, which still contains a literal `PRAGMA user_version = 1` — and the most natural reading of "in line with" is to copy it, reintroducing the reset-on-every-open behaviour. Now called out explicitly, alongside the second thing that file must not do silently: bringing the DDL in line breaks the existing tests in `api/ffi_api.rs`, which insert without `content_hash` and without `fts_mapping.workspace_id`, both now `NOT NULL`.

### Corrections from PR review, round 6
Folded into v1.1.0.

- **I miscounted OKF §11, in the same section round 1 flagged for invented citations.** Round 5 asserted "exactly two conformance conditions" in three files. ### Corrections from PR review, round 7
Folded into v1.1.0.

- **The mid-focus write updated every span except the one that changed length.** ADR-008 decision 2 said tier 2 "splices the buffered source and shifts every later span by the byte delta". Worked through concretely in the ADR now. Rather than patch the sentence, the design was corrected so the class cannot recur: there is exactly **one** writer of the working source. `update_block` substitutes and adjusts the spans (resizing the edited one, shifting the rest); tier 2 writes that buffer verbatim and splices nothing.

Reconciled by narrowing rather than by asserting: risk 7 is about arithmetic replacing a reparse across a **structural** change, where errors are silent; `update_block`'s adjustment is one span's end plus a uniform shift, within a Block whose structure is not re-derived until `commit_block` reparses. Reproduced against the schema as written. It is worse than the delete path because reindex runs on first open, after a merge, and on recovery. Now stated on the table, in `WSPC-D005`'s description, and as a STOP and a criterion.
- **The contract still asserted the §11 count round 6 declared false**, saying "OKF §11's two conformance conditions". It survived round 6's sweep because the phrase breaks across a comment wrap, so a line-oriented grep does not find it — and it was the one machine-facing site, the surface an implementer reads while writing the check. ### Corrections from PR review, round 9
Folded into v1.1.0.

- **Renaming an *open* Note was unspecified against every piece of per-open state, and each way of getting it wrong is a defect.** `rename_note` writes the Note's bytes, which makes it the one exception to ADR-007's single-writer rule — and nothing said what happens to the working source, the span map, or the recorded revision. Leave the buffer alone and the next tier 2 write, which copies it verbatim, silently reverts the title. Leave the revision alone and the next write raises `RevisionMismatch` against this application's own rename — the **fourth** appearance of the baseline-drift shape three earlier rounds each removed one layer at a time; it reappears here because renaming is the only other thing that writes the file. And `WSPC-D006`'s criterion actively mandated preserving the stale bytes ("the drafted content is intact"), which combined with the draft being parsed in preference to disk means reopening restores the old title. All three obligations are now stated on `rename_note`, inherited by `move_note` and `rename_directory`, with a criterion.
- **Tier 2's failures had no return channel.** The routine trigger is a Core-owned idle timer, so when its write fails there is no caller to return the error to — and there was no stream, callback or poll anywhere in the 39-function contract. That makes `RevisionMismatch`, which is the entirety of risk 6's mitigation, raised into nothing; likewise `DiskFull` and `IoError` from the same path, leaving the user typing into a buffer nothing can persist, in an application that deliberately shows no save control so they will trust it. A specified control with nowhere to be acted on is exactly the OAuth `state` shape. Added `note_write_status(note_id)` — a poll rather than a stream, matching the `sync_status` precedent — and gave `SHEL-E007` the surface, a STOP and two criteria.
- **A draft row does *not* mean "differs from disk", which is the justification the open sequence rests on.** Tier 2 wrote the file and left the draft; only tier 3 cleared it. So after any mid-session idle write the row exists byte-identical to disk — the common case for any session ending without a clean close — and `pending_drafts`/`restored_from_draft` would report recovered work for Notes where nothing was lost. Reporting a false alarm on the common path is how a real one stops being believed. Tier 2 now clears the draft on success, which makes the sentence true rather than merely repaired.
- **Risk 6's Mitigation still specified the design three rounds removed** — a caller-supplied `expected_base_revision` on a `save_note` that no longer exists. The appended Resolution redefined the token but never recorded that the parameter itself was deleted, so an implementer reading the Mitigation as the specification rebuilds precisely what rounds 2, 3 and 5 dismantled. Marked superseded, using the convention the same file already applies to its Epic B notes.
- **The Format Conformance constraint was falsified by a workflow this PR makes explicit.** It promised conformance for every Note the application "writes", while `okf-bundle.md` decides that repairing a non-conformant foreign file is an explicit user action no ticket implements — so editing such a file writes it and leaves it non-conformant. Round 3 caught this shape on `CAP-PORT-01` and rescoped it to "writes", which is the ambiguous word. Pinned to **creates**, with the exception stated where the constraint is stated rather than three documents away.
- **`open_workspace` was a third bootstrap path that did not converge.** ADR-005 required initialize-local and clone to end in the same state "so that no later code needs to ask which path produced the Workspace it is looking at"; `open_workspace` neither creates a directory nor initializes a repository, and tier 3 commits on every Note close. In a Workspace adopted that way, CAP-WS-02 is unsatisfiable and `close_note` fails on the routine path. ADR-005 decision 7 now has it initialize a repository when there is no history, with the side effect owned rather than discovered on the first close.
