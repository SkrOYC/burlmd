# Provisional Forward Contract

## Purpose

This document prevents the research wave from becoming an accidental implementation wave. Structured PRD v2.0.5 and Architecture v2.1.2 are binding. The delivered v1.6.x physical contracts remain valid only for already-delivered behavior. Where they conflict with the forward constitution, the forward requirement is authoritative.

The release control surface treats the following scripts as immutable trust-anchor controls:

- `scripts/write-receipt-digest-observation.sh`
- `scripts/prepare-compatibility-stage.sh`
- `scripts/record-compatibility-stage-rest.sh`
- `scripts/write-compatibility-stage-lineage.sh`
- `scripts/prepare-compatibility-stage-consumer.sh`
- `scripts/validate-compatibility-stage-interface.sh`

Each reusable role workflow exposes its receipt upload artifact ID and bare digest through exact workflow outputs. The caller's fresh `receipt_digests` job maps all six values into one identity-bound transport without downloading candidate bytes.

Local collection resolves the transport's immutable artifact ID from the exact run inventory. It downloads the raw archive by ID and compares its SHA-256 with the canonical REST digest before extraction. The aggregate retains this check in `receiptDigestTransportArtifact`. Collection then validates the transport and checks each receipt ID and name against REST. It requires each receipt's REST digest to equal `sha256:` plus the transported action digest. The aggregate retains both receipt digest forms in `origin.sealingReceiptArtifact`. The sealing receipt remains version `2` and contains only pre-upload facts. Transport verification detects corruption or substitution but doesn't provide provenance independent of GitHub's artifact service.

Static workflow-shape fixtures use duplicate-aware source parsing to pin the exact ordered 26 producer-output keys, consumer string-input keys, and observable trusted mappings. They also pin every canonical hyphenated consumer input through its uppercase environment variable into the validator's ordered 26-field inventory. Before caller mapping, the macOS 26 output boundary normalizes the three producer sealing aliases for every ticket other than `BURL-O001`. It doesn't rely on omitted reusable-workflow input defaults.

Before acquisition or consumer processing, the macOS 15 trusted workflow wrapper invokes `scripts/validate-compatibility-stage-interface.sh`. Accepted nonempty `BURL-O001` values proceed to all three artifact downloads, offline verification, and `scripts/prepare-compatibility-stage-consumer.sh`. Accepted all-empty values for every other ticket skip only those compatibility steps, then continue the ordinary candidate path. The runtime shell can't validate source key shape or arbitrary value provenance. `scripts/prepare-compatibility-stage-consumer.sh` validates the result files. Downstream checks validate the values it consumes. The script then removes credentials and exposes only verified read-only members to the macOS 15 candidate.

In-workflow validators require literal `GITHUB_RUN_ATTEMPT=1` before relevant work. Local collection requires literal `--attempt 1` and REST `.run_attempt == 1` before acquisition. It re-fetches that exact REST object and requires numeric `.run_attempt == 1` immediately before atomically publishing an accepted report. Local collection does not inspect `GITHUB_RUN_ATTEMPT`. The launcher uses PR #15's `od -An -N16 -tx1 /dev/urandom | tr -d ' \n'` mechanism to generate each 128-bit nonce. It fails closed without a fallback unless the result is exactly 32 lowercase hexadecimal characters. A failed, cancelled, timed-out, or rejected report requires a fresh `workflow_dispatch` run with a new nonce and workflow run ID. GitHub UI and API reruns are forbidden. A recording fake API fixture proves that every path in the complete `trusted_control_paths` inventory makes no artifact-deletion request. Static fixtures require the exact 11-artifact ordinary and 13-artifact BURL-O001 inventories and `overwrite: false` on every upload. A byte or mode change in any helper requires reviewed trust-anchor rotation and evidence-only completion.

ADR-020 and raw contract version `36` define one additional implementation detail for `BURL-M003`: an exact read-only Bubblewrap view of its complete locked candidate runtime closure. A pre-namespace check requires a fresh staging leaf under its frozen stable parent for every session. The leaf contains only empty, source-distinct placeholders. The view hides the host store root, `/nix/var`, the Nix database, the daemon socket, Bubblewrap, and unlisted paths. A fresh trusted preflight verifies every member's decoded mountinfo root, device, read-only option, file type, `st_dev`, and `st_ino` against the same read-only host-source identity for every session. An omitted bind or copied placeholder can't pass visible-name equality alone. Static source fixtures permit only the owned-store base, same-path manifest-member binds, and one `--symlink` from the mounted canonical store-backed `env` to `/usr/bin/env`. Every other bind-family option involving `/nix`, any bind at `/usr/bin/env`, and any broad `/usr` bind fails. A `#!/usr/bin/env bash` fixture proves the symlink. A fixture that hides copied state beneath valid member binds fails the staging-shape check before Bubblewrap starts.

The candidate root inventory includes locked Diffutils `3.12` for `cmp` and locked Procps `4.0.6` for `ps`. `BURL-M003` must declare both Nix packages and require their exact store paths. A root-resolution result under ambient `/usr`, `/run/current-system`, or another non-store root fails before candidate execution. Two pinned-Nix reproductions produced the same candidate measurements: 549 paths, a 34,418-byte manifest, SHA-256 `c82bb681b260902382f9a747d0f8588ab29bb1d8d56cec0f7b7c30fc368399d9`, 6,338,161,576 summed Nix archive (NAR) bytes, and 74,326 bind-only argument bytes. The unchanged parent tool closure has eight paths, a 480-byte manifest, SHA-256 `398d11c9cd9249369cbb18d36661014eafef5ac18ff7adeb076c2c51ef0141fd`, 40,679,016 summed NAR bytes, and 1,040 bind-only argument bytes.

The trusted parent keeps Bubblewrap in a separate eight-path tool closure. It proves the exact canonical store path, `bubblewrap 0.11.2` output, executable SHA-256, and tool-closure manifest SHA-256. Bubblewrap doesn't enter the candidate closure or `PATH`. An exact-path candidate probe returns `ENOENT`, and a command-name invocation returns status `127`.

The binding BURL-M003 Linux sequence contains seven ordered session IDs: four fixed gates, two path-hash integration gates, and the final managed-isolation gate. Each integration hash covers only the repository-relative path's exact UTF-8 bytes. It has no byte-order mark, normalization, delimiter, or terminator. The trusted parent invokes the pinned Bubblewrap executable once per ID. Each invocation uses the exact namespace flags from raw contract version `36`, including `--disable-userns` and `--assert-userns-disabled`. The in-namespace preflight and candidate don't execute another Bubblewrap process. They assert only the resulting namespace, mount, process, descriptor, and network properties. The view preserves ADR-0019's Linux isolation controls and OD-11 authority.

Each preflight begins with candidate standard streams fixed as descriptors 0 through 2. Descriptor 3 is the preflight-record write end, and descriptor 4 is the acknowledgement read end. The parent owns only the opposite ends. The wrapper closes descriptor 3 after its length-prefixed record. The parent validates the complete record and end of file before it sends ASCII `G` and closes its acknowledgement end. The wrapper requires `G` and end of file, closes descriptor 4, verifies each standard stream's recorded file type, device, inode, decoded `/proc/self/fd` target, and access mode, and requires the exact descriptor set 0 through 2. It then replaces itself with the candidate. No handshake descriptor survives candidate exec.

Before the first candidate session, the launcher freezes every BURL-M003 capacity authority as a stable parent, device, and decoded containing-mount identity. The set covers checkouts, caches, build and generated output, temporary and output storage, candidate state, closure staging, session storage, private Sway runtime, writable-bind sources, and writable environment paths. Each capacity slot uses either its stable parent or one declared per-session staging, session, or writable-bind leaf. The launcher creates ephemeral leaves only under their declared parents. Before namespace entry, it canonicalizes current leaves without following links. Every descendant component must retain the frozen parent mount ID, and the leaf must retain the parent's `st_dev`. It records only current-session leaves, removes them after the session, and doesn't stat removed earlier leaves during later sessions. No step can add a parent, mount, device, capacity slot, leaf declaration, or writable path outside the frozen authority set. The launcher groups frozen parent authorities by distinct `st_dev` and applies the 4,000,000,000-byte start guard to every device. An omitted authority and a low-space secondary stable device fail closed. This is a start guard, not a phase transcript, peak measurement, or `BURL-O001` packaging claim.

The Linux role retains one `logs/burl-m003-linux-closure-view.log` through the unchanged `roleEvidence.internalArtifacts` fields. Raw contract version `36` defines the log's exact byte grammar, length-prefixed preflight record, escaping, tokens, literal manifest delimiter, final-byte rule, and canonical golden fixture. Its header contains the exact parent-only Bubblewrap identity, tool-closure digest, candidate-manifest identity, and source identity. Seven session frames retain the exact manifest, source, namespace-flag, unique staging-root, preflight, complete-vector, stable-parent-to-current-path, start-space, teardown, and cleanup proof for every invocation. The golden checks bind seven distinct staging leaves to one stable parent and reject a removed prior leaf, undeclared leaf, symbolic-link escape, nested mount, device mismatch, and low-space secondary stable device. Fresh sealing validates those bytes and values. Accepted aggregation embeds the role manifest and binds the unchanged role and sealed bundle digests. This evidence path doesn't add a role-schema field, aggregate-schema field, or service artifact.

## Contract-scoped production authorization

The Epic G M0 production exceptions remain in force. `BURL-M015` and `BURL-M003` may also implement the reproducibility and managed-validation bootstrap in this TechSpec. Within `BURL-M003`'s existing `devenv.nix`, `devenv.lock`, and `scripts/**` scope, Stage 4 may adapt the two locked package declarations, per-session lifecycle, and retained proof. The adaptation includes the `env` symlink, parent-only Bubblewrap tool closure, candidate absence probes, exact seven-session inventory and serialization, descriptor handshake, log grammar, frozen stable capacity authorities, fresh per-session leaves and preflight, exhaustive per-device start guard, teardown, and cleanup. It must preserve one namespace per session, no nested or candidate Bubblewrap, no network, private PID ownership, and exact closure-view identity. It must add or retain a `BURL-O001` stop condition that routes Linux Nix packaging isolation and capacity to a later Stage 3 decision. This patch doesn't authorize or solve that `BURL-O001` work. `BURL-M003` owns the missing `scripts/check-generated-bindings.sh` file and must create the non-mutating checker before any bootstrap gate invokes it. The checker snapshots and backs up both generated surfaces. It runs the provisional Flutter Rust Bridge `2.12.0` generator, compares file sets and bytes with the locked Diffutils `cmp` path, and reports stale output. The checker restores the exact precheck state before exit. Implementation must follow the accepted contract without importing or cherry-picking the coordinating Epic G branch. This authorization doesn't settle any open AST, path, asset, Git, observer, packaging, or release choice.

Every other production ticket remains blocked until its own decision evidence lands. Product Requirements and Architecture are reviewed when that evidence changes an upstream assumption. Final Stage 3 then replaces that ticket's provisional physical contract, and Stage 4 adapts the ticket before implementation. A ticket doesn't wait for an unrelated Spike, and one completed Spike doesn't authorize neighboring production work.

Spike Tasks may read production code and fixtures but may write only within their prototype roots and report records. Final Stage 3 still owns the reconciled FFI, schemas, bill of materials, repository layout, error taxonomy, and exact implementation commands for each affected contract.

## Known brownfield contradictions

- `ffi_api.rs` describes `AstNode` as a render projection, while the forward model requires a canonical extended AST.
- The OAuth redirect and PKCE surfaces require a client-secret-era design superseded by GitHub App device flow.
- The OKF bundle derives filenames verbatim from titles, which OD-05 explicitly reopens.
- The schema and open-Workspace comments tolerate and index invalid Notes, while the authority model now excludes them until Repair or Exclude.
- `export_workspace` describes partial, non-gating output; forward Export must be object-complete and atomic.
- Git Suggestions assume marker-bearing content conflicts and don't cover Lifecycle or Asset Decisions.
- No physical model exists for Workspace observation, S3-compatible object configuration, asset reachability, or release metadata.
- PR #15 at `9719259f1ecee819af96c98c2be210156f198343` copies the Linux candidate closure into a private store. Its measured prebuild allocation exceeds the standard runner profile. `BURL-M003` must use ADR-020 and raw contract version `36`. `BURL-O001` remains blocked on a later Stage 3 packaging-isolation and capacity decision.

These are tracked inputs to final reconciliation, not defects for a research Task to patch piecemeal.
